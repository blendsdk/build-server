# build-server — project guidance

## Overview

- **Type:** Infrastructure / DevOps tooling (no application source code).
- **Purpose:** Self-hosted GitHub Actions runner fleet — one persistent, privileged runner per
  GitHub organization plus a co-located private Docker registry. Each runner container runs its
  **own Docker daemon**; the host Docker socket is never mounted. The fleet is driven by
  `orgs.conf` and managed with `fleet.sh`.
- **Languages:** Bash, Dockerfile, Docker Compose YAML. Tests are Bash. Docs are Markdown
  (VitePress).

## Commands

| Command | Purpose | Status |
| ------- | ------- | ------ |
| `bash test/verify.sh` | Authoritative verification: shellcheck + all spec/implementation tests + tree checks | Verified |
| `npm ci && npm run docs:build` | Build the VitePress documentation site | Verified |
| `npm run docs:dev` | Live docs preview | Verified |
| `bash examples/playground.sh` | Offline CLI playground with stub docker/curl | Verified |
| `./fleet.sh generate / build / up / down / clean / upgrade-all / status` | Fleet operations | Build-host only |
| `bash bootstrap.sh [--no-start]` | Fresh-host install | Build-host only |

Run `bash test/verify.sh` before every commit; CI runs the same command on GitHub-hosted runners.

## Structure

```
bootstrap.sh              Fresh-host installer
orgs.conf                 Organization registry (url=, context=, build_temp=1)
fleet.sh                  Admin CLI: generate/build/lifecycle/update/status
docker-compose.yml        Static base: the private registry
Dockerfile                Runner image (Ubuntu 24.04, inner Docker engine, Actions runner)
entrypoint.sh             Starts the private daemon, supervises the runner
start.sh                  Registers the runner, runs it, deregisters on shutdown
docs/                     VitePress site (GitHub Pages)
examples/                 Offline playground and smoke-test recipe
test/                     Spec tests (*.spec.test.sh), impl tests (*.impl.test.sh), verify.sh
codeops/                  CodeOps artifacts (nested layout; feature plans under features/)
```

## Conventions

- **Spec tests first:** `*.spec.test.sh` encode documented behavior; a failing spec test means the
  implementation is wrong, never the test. Implementation tests use `*.impl.test.sh`.
- Shell scripts use `#!/bin/bash` and `set -euo pipefail`; shellcheck (`-S style`) must stay clean.
- `fleet.sh` changes into the repository root and loads `.env` when present; generated and staged
  files (`docker-compose.generated.yml`, `.runner-version`, `.fleet-build/`) are gitignored.
- Keep the host Docker socket out of runner services; runners are privileged and run their own
  daemon. Daemon shutdown is owned by `entrypoint.sh`.
- Never commit host-local files: `.env`, `.npmrc`, `.yarnrc`, `.bunfig.toml`, `config.json`,
  `ssh/`.
- Update `docs/` when behavior, commands, or configuration change.
